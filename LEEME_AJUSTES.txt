GEI PANAMÁ · v2.12 · VARIOS ANÁLISIS POR FECHA

IMPORTANTE: ESTA VERSIÓN SÍ REQUIERE UNA ACTUALIZACIÓN EN SUPABASE.
1. Abre actualizar_analisis_por_fecha.sql con Bloc de notas y copia su contenido.
2. En tu proyecto de Supabase: SQL Editor > New query, pega el contenido y Run.
   Debe terminar con Success / No rows returned. Ejecuta solo este archivo;
   NO vuelvas a ejecutar base_de_datos.sql en tu proyecto existente.
   Si avisa de una finca y fecha repetidas de versiones anteriores, comparte
   ese mensaje para revisar las fechas reales: el proceso no habrá borrado datos.
3. Extrae y sube los archivos de la app al mismo repositorio de GitHub.
4. Tras terminar el despliegue, recarga con Ctrl+F5 y comprueba v2.12.

FUNCIONAMIENTO
- En Ver emisiones > Nuevo análisis de esta finca, elige la fecha que necesites.
- Puedes registrar análisis cada 3 meses, 6 meses o cualquier intervalo.
- Una finca no puede tener dos análisis con exactamente la misma fecha.
- Se conserva el código de finca y cada diagnóstico anterior con sus factores.
- El año del nuevo análisis se toma de la fecha elegida; no se fuerza otro año.
- La consulta por cédula y el historial muestran todas las fechas en orden.
- Las comparaciones usan el análisis anterior por fecha y el CSV incluye esa fecha.
- En el consolidado territorial se utiliza el último análisis de cada finca
  dentro del año/selección, para no sumar varias veces una misma finca.
  La lista y las exportaciones conservan todos los análisis individuales.
- Los resultados siguen expresados como estimaciones anuales (t CO2e/año).
  Registrar cada trimestre no convierte el resultado en emisiones trimestrales.
- Los registros históricos sin fecha no reciben una fecha inventada. Para guardar
  una edición en la app, indica la fecha correcta del diagnóstico.
- Se mantienen conteo principal de animales, UG/ha de pastos, desglose de áreas,
  ventana ampliable, desplazamiento interno y limpieza después de guardar.

El SQL no borra datos ni cambia permisos y no toca las tablas de BioMarket.
